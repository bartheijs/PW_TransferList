# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

This is a Mendix Pluggable Widget (`TransferList`) that allows Mendix app users to transfer objects from one list to another.

- **Package path:** `conclusion low code company.transferlist`
- **Supported platform:** Web only
- **Tooling:** `@mendix/pluggable-widgets-tools` v10.15.0

## Documentation

`README.md` is the end-user documentation for Mendix developers integrating this widget. Keep it up to date when widget properties or behaviour change — in particular the **Features** and **Usage** sections.

## Commands

```bash
npm install        # Install dependencies (use --legacy-peer-deps if npm v7+)
npm run dev        # Start dev server with hot reload (web)
npm start          # Start server mode (copies bundle to Mendix test project on change)
npm run build      # Build widget (development)
npm run release    # Build widget (production, runs lint first)
npm run lint       # Run linter
npm run lint:fix   # Auto-fix lint issues
```

> **Note:** `npm run release` runs `lint` as a pre-step, so a clean lint is required to release. No test runner is configured.

## Architecture

### Key files

| File | Purpose |
|------|---------|
| `src/TransferList.xml` | Widget property definition (read by Mendix Studio Pro) |
| `src/TransferList.tsx` | Main runtime component |
| `src/TransferList.editorPreview.tsx` | Studio Pro canvas preview |
| `src/TransferList.editorConfig.ts` | Studio Pro property panel config |
| `src/ui/TransferList.css` | Widget-specific styles |
| `typings/TransferListProps.d.ts` | Auto-generated prop types — **never edit manually** |

### Data flow

Widget properties defined in `TransferList.xml` → auto-generates `typings/TransferListProps.d.ts` → imported as `TransferListContainerProps` (runtime) and `TransferListPreviewProps` (Studio Pro preview).

### Mendix-specific patterns

- Widget props are typed via `TransferListContainerProps` (auto-generated from the XML).
- When working with dynamic values from a datasource, check `status === ValueStatus.Available` before accessing `.value`.
- `needsEntityContext="true"` in `TransferList.xml` means the widget must be placed inside a data view or similar context.
- The `packagePath` in `package.json` (`conclusion low code company`) determines the namespace used in the widget ID and the output folder inside `dist/`.
- `config.projectPath` (`../../`) points to the Mendix test project root; `npm start` copies bundles there automatically.
- Prettier is configured with `@prettier/plugin-xml` so XML widget definition files are also formatted.
- The `typings/*.d.ts` file is regenerated by `npm start` — editing it manually will be overwritten.
- Property `<caption>` text in `src/*.xml` is capped at **24 characters** (exception: `type="widgets"` properties have no limit).

## Coding Guidelines

_Source of truth: `MX_PW_WEB_CODING_GUIDELINES.md`_

- Use React, JavaScript, and TypeScript.
- Use functional and declarative programming patterns; **never use classes**.
- Use functional components with TypeScript interfaces. Prefer `interface` over `type`.
- Use declarative JSX.
- Prefer iteration and modularization over code duplication (DRY).
- Consider using early return patterns.
- Place hardcoded values in `CAPITALIZED_CONSTANTS` at the top of the file.
- Always add JSDoc documentation in English when creating new functions and classes.
- Add comments to explain the code in English.
- Filenames are always descriptive and in English.
- **Logging:** only `console.warn` or `console.error`. Import `LOG_PREFIX` from `src/constants.ts` and pass it as the first argument (e.g. `console.warn(LOG_PREFIX, "message")`). Log messages in English.
- Ensure high accessibility (a11y) standards using ARIA roles and accessibility props.
- Use Prettier for consistent code formatting.
- **Never edit** `typings/*.d.ts` — regenerated automatically by `npm start`.
- Property `<caption>` text in `src/*.xml` is capped at **24 characters** (exception: `type="widgets"` properties have no limit).
